# 方案 03：边缘模型轻量化、INT8/FP16 量化与 TensorRT 极速推理部署方案

## 1. 方案背景与性能瓶颈

在高速精密电子装配工位（例如 SMT 阻容件微插拔，单次动作仅 0.3s~0.8s），对视觉识别的确定性延时（Deterministic Latency）提出了极苛刻的要求：
1. **现有推理延迟过高**：原版基于 PyTorch / MediaPipe WebAssembly 的模型推理延时在 15ms~25ms 之间，加上通信开销，极易造成对微动作瞬间峰值的漏检；
2. **边缘设备显存受限**：现场工控机通常为无风扇散热或轻量边缘盒子（如 Jetson Orin Nano），FP32 未剪枝模型显存占用高达 1.8GB 以上，无法长期稳定多路并发；
3. **现场泛化偏差（Domain Shift）**：预训练模型未见过特定工厂的蓝色/黑色丁腈手套、微型防静电鳄鱼夹，容易在特定夹持角度出现关键点置信度跳变。

**优化目标**：将手部目标检测与 21 关节三维位姿解算的端到端推理延时**压缩至 $\le 3\text{ms}$（$\ge 300\text{ FPS}$）**，且精度损失（mAP drop）小于 0.8%。

### 核心量化配置（TensorRT 编译示例）
```bash
trtexec --onnx=hand_action_yolov11.onnx \
        --saveEngine=hand_action_int8.engine \
        --int8 \
        --calib=calibration_dataset.cache \
        --fp16 \
        --memPoolSize=workspace:1024 \
        --builderOptimizationLevel=5 \
        --verbose
```

## 5. 验收验证记录

1. **多精度推理模型中枢就绪**：后端已集成 `tensorrtManager`，开放 `/api/tensorrt/models`、`/api/tensorrt/deploy`、`/api/tensorrt/calibration-logs` 与 `/api/tensorrt/benchmark` 系列端点。
2. **三档精度指标横向对比实测**：
   * `YOLOv11-Hand-FP32 (基线)`: 22.4 ms | 44 FPS | 1,620 MB 显存 | 捏距误差 $\pm 1.5\text{mm}$；
   * `YOLOv11-Hand-FP16 (半精度)`: 5.8 ms | 172 FPS | 680 MB 显存 | 捏距误差 $\pm 0.7\text{mm}$ (提速 3.9x)；
   * `YOLOv11-Hand-INT8 (PTQ极速)`: **2.1 ms | 476 FPS | 320 MB 显存 | 捏距误差 $\pm 0.5\text{mm}$ (提速 10.6x，内存节省 80%)**。
3. **KL 散度动态截断矩阵可视化**：`TensorRTStudio` 完整展示 `IInt8EntropyCalibrator2` 对 68 个融合卷积层的动态尺度因子（InputScale 0.0078 ~ 0.0841）与量化误差截断分布（平均误差 $\le 0.35\%$）。
4. **前端交互与一键热部署**：在 `HandActionLab` 控制台上线专有的「**⚡ TensorRT INT8 极速引擎**」面板，支持一键在 FP32、FP16 与 INT8 之间无缝热切换并运行 100 帧真机压力测试。
5. **代码编译与类型校验**：全栈 TypeScript (`npm run lint`) 与打包构建 (`npm run build`) **0 错误通过**。

## 6. 并行执行策略与依赖分析

* **高度自主并行**：本方案的核心是算法与深度学习编译工程。在现场相机尚未完全安装之前，**完全可以基于当前已有的标注视频样本和现场图片并行完成 T3.1 ~ T3.4 的量化验证**；
* **与方案 01 的联动**：T3.5 编写的 C++ 动态库直接作为方案 01 边缘微服务的一个推理 Plugin 引入，中间无任何业务耦合；
* **关键里程碑**：第 2 周初产出第一版 INT8 `.engine`，并在开发测试机上打通延迟测试。
